Indexatron started as a simple question: can I use a local vision model to automatically organise thousands of family photos without sending a single image to the cloud? The answer is yes. The hypothesis is confirmed and it is now integrated into the-mcculloughs.org. How it works: Ollama runtime running locally. LLaVA 7b as the vision model — about 4.7 gigabytes. nomic-embed-text for 768-dimensional semantic embeddings at 274 megabytes. Python 3.11 gluing it together. Each photo goes through the pipeline and comes out with: subject identification, scene categorisation, a date estimate or an override if we have the actual date, family nickname resolution, and a semantic embedding for search. Key learnings from building it: Context matters more than the model. Injecting existing metadata into the prompt — date, location, album name — significantly improves what the model produces. The model is not guessing blind. LLaVA 7b is more reliable than Llama 3.2 Vision for structured JSON extraction. Smaller model, more predictable output. That was a surprise. Vision models need defensive JSON parsing. They will go off-format. Build for it. The privacy angle is not a gimmick. The whole point of the-mcculloughs.org is that family history stays on infrastructure I control. Running the analysis locally is consistent with that. Development ran from February to April 2026. This talk came out of a real experiment, not a thought experiment. Step 1: raw transcripts for all five seasons, sixty episodes, every line of dialogue. Step 2: speaker attribution. The problem with raw transcripts is they give you the dialogue but not always who said what. AI worked through the attribution, normalised character names, and pulled out who was talking to whom and about whom. That gives you the relational layer. Step 3: Neo4j. Characters as nodes. Relationships as edges. Cypher queries for shortest paths between characters, centrality metrics to find the connectors, community detection to see which clusters formed. That analysis is what shaped the model on the next few slides. Step 4: static export. The deck and the explorer both run from wire-graph.json, a snapshot of the Neo4j model. The Cypher panel in the explorer shows the equivalent live query. The demo is reproducible offline, and the numbers on the next few slides come straight out of the same export. Key point: "I wanted to test this rather than just talk about it. So I ran the data first." The full working, including the pipeline, the transcripts, and the queries, is up at experiments.swm.cc if anyone wants to dig into it after.
